# M10 — Robustez do núcleo (Fase 3)

> Uma fase por sessão (M8→M9→M10→M11). Este doc é o mini-design para revisão
> antes de implementar. Fonte: `PROMPT_FASES_CORRECAO.md` Fase 3.

## D1 — `ToolResult` tipado (3.1)

- Novo modelo Pydantic **frozen** `ToolResult` em `nullain/tools/result.py`:
  `output: str`, `is_error: bool = False`, `error_type: str | None = None`.
- `RegisteredTool.execute` e `ToolRegistry.execute` passam a retornar
  `ToolResult` (não `str`). Ponte de compatibilidade: resultado `str` de tool
  legada é envolvido em `ToolResult(output=..., is_error=False)`; `ToolError`
  levantado vira `ToolResult(is_error=True, error_type=...)`.
- Loop usa `result.is_error` em vez de `ERROR_OUTPUT_PREFIXES` (removido).
- `SpecValidator.verify` migra de `startswith(BASH_NONZERO_PREFIX)` para
  `cmd_res.is_error` (o `bash` tool retorna erro estrutural).

## D2 — Cancelamento (3.2)

- **`anyio.CancelScope`** (já é dependência) em vez de `CancellationToken`
  custom: é o primitivo idiomático, propaga para tasks filhas e aguarda
  cleanup. Justificativa: sem nova dependência, sem reimplementar.
- `AgentLoop.run*` envolve o corpo num `CancelScope`; o provider aborta o HTTP
  em voo, a execução de tool mata o subprocess, `spawn` de subagente cancela
  filhos em cascata.
- Novo membro `"cancelled"` em `RunStatus`; run cancelado retorna
  `RunResult(status="cancelled")`, não exceção crua. Daemon cancela em
  `session.cancel` / stdin fechado.

## D3 — Fold incremental (3.3)

- Cachear `ConversationState` e atualizá-lo incrementalmente ao anexar eventos;
  invalidar em `CompactionEvent`. `fold` permanece função pura; o cache é
  otimização **verificável**.
- Property test (hypothesis): resultado incremental == fold completo para
  qualquer sequência de eventos.
- Eliminar o fold duplicado entre `_check_budget_and_compact` e
  `_build_messages` no mesmo passo (compartilhar o estado derivado).

## D4 — Merge de deltas de tool-call no streaming (3.4)

- Acumular `arguments` por índice/id: fragmentos concatenados; a call só é
  completa quando o JSON parseia ou o stream termina. Cobrir `endpoint_type`
  `v1` (OpenAI-compat) e `native` (Ollama).
- Teste com stream fake fragmentando args em 3+ chunks no meio de um token JSON.

## D5 — Contagem real de tokens (3.5)

- Preferir o `usage` que o provider devolve quando disponível; manter
  `len//4` como fallback. **Não** adicionar `tiktoken` (nova dependência —
  regra 10; o caminho provider-usage já é a contagem real).
- Interface `estimate_tokens`/`estimate_context_tokens` estável; mudança só de
  implementação. Teste comparando estimativa vs `usage` real de resposta fake.

## Definition of done

- Teste de regressão para cada um dos 5 defeitos (falha no código antigo).
- Property test do fold incremental. `make check` verde.
- Commit: `fix(m10): typed ToolResult, cancellation, incremental fold, stream delta merge, real token count`.
