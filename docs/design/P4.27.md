# P4.27 — Workflow Orchestrator (Deterministic over Subagents)

> **Determinism property.** A workflow is a Python function that orchestrates
> subagents through a fixed, scripted structure — which subagents run, in what
> order, with what fan-out and pipeline stages is decided by the script, never
> by an LLM. The orchestration is deterministic; only the subagent outputs are
> non-deterministic (they are LLM calls). This is the equivalent of Claude's
> `Workflow` tool, expressed as a native Python DSL.

## Why it matters

`AgentLoop.spawn` (P4.24) gives a single subagent with fresh context and an
authority-intersected tool view. But orchestrating *many* subagents — fan-out a
search across modules, run a review pipeline, verify findings adversarially —
is left to the parent loop, which is model-driven and non-deterministic. A
workflow makes the orchestration explicit and repeatable: the same script
produces the same fan-out/pipeline structure every run, so a multi-agent task
is auditable, resumable, and testable.

This composes the prior P4 guarantees:

- **P4.24 authority law** — each `agent()` call delegates an authority that is
  intersected with the subagent's own surface and the policy. A workflow cannot
  grant a subagent more than the parent holds.
- **P4.25 plugins / P4.26 tool search** — subagents inherit the registry, so
  workflow agents see the same signed, capability-manifested, deferred-schema
  tools as the parent.

## Model (`nullain/workflow/`)

### `WorkflowSpawner` — the subagent port

```
Protocol: async __call__(prompt, *, label, model, max_steps, authority) -> str
```

A callable that runs one subagent and returns its final text. `loop_spawner(loop)`
adapts an `AgentLoop` (delegating to `AgentLoop.spawn`), so the orchestrator is
decoupled from the loop and testable with a fake spawner.

### `WorkflowContext` — the DSL surface

Passed to the workflow function. Provides:

- `args` — the workflow's input value (verbatim).
- `phase(title)` — set the current phase (groups progress).
- `log(message)` — emit a progress message.
- `agent(prompt, *, label=None, model=None, max_steps=None, authority=None) -> str`
  — spawn a subagent via the spawner.
- `parallel(thunks) -> list` — run thunks concurrently (**barrier**: awaits all
  before returning). A thunk that throws resolves to `None` in the result; the
  call never rejects.
- `pipeline(items, *stages) -> list` — run each item through all stages with
  **no barrier** between stages (item A can be in stage 3 while item B is in
  stage 1). Each stage receives `(prev_result, original_item, index)`; a stage
  that throws drops that item to `None` and skips its remaining stages.

### `Workflow` — the definition + runner

```
Workflow(name, description, fn)   # fn: async (ctx: WorkflowContext) -> Any
await workflow.run(spawner, *, args=None, event_bus=None, session_id="workflow") -> Any
```

`run` builds a `WorkflowContext` bound to the spawner and emits progress events
(phase/log/agent) to the event bus, then awaits `fn(ctx)` and returns its result.

### Progress events (`events/types.py`)

- `WorkflowPhaseEvent` — a phase started.
- `WorkflowLogEvent` — a progress message.
- `WorkflowAgentEvent` — a subagent started / completed / failed (with output).

These let the daemon report workflow progress without coupling the orchestrator
to a specific transport.

## Determinism and honesty

- **The orchestration is deterministic; the outputs are not.** The script fixes
  the fan-out/pipeline structure; each `agent()` is an LLM call whose text is
  non-deterministic. This is the intended property — repeatable structure,
  variable content.
- **v1 `agent()` returns text only.** Structured output (a JSON schema the
  subagent must conform to) is a documented follow-up; the spawner signature is
  stable either way.
- **v1 has no token budget.** A `budget` guard (stop spawning once a token
  ceiling is hit) is a documented follow-up; the context/runner surface is
  stable either way.
- **v1 is synchronous-in-place** (matches `AgentLoop.spawn`): the workflow
  awaits each subagent. Background/durable workflows are a follow-up.

## Proof

`tests/unit/test_workflow.py` (offline; fake spawner, no LLM):

- `test_agent_returns_spawner_output` — `agent()` returns the spawner's text.
- `test_agent_passes_authority_and_model` — spawner receives delegated opts.
- `test_parallel_runs_concurrently_and_barriers` — all thunks awaited before
  return; results in order.
- `test_parallel_resolves_thunk_exception_to_none` — a throwing thunk yields
  `None`, the call does not reject.
- `test_pipeline_runs_stages_per_item_no_barrier` — each item through all
  stages; stage receives `(prev, item, index)`.
- `test_pipeline_drops_item_when_stage_throws` — a throwing stage drops that
  item to `None` and skips its remaining stages.
- `test_phase_and_log_emit_events` — phase/log emit `WorkflowPhaseEvent` /
  `WorkflowLogEvent`.
- `test_agent_emits_start_and_complete_events` — `WorkflowAgentEvent` for
  started/completed.
- `test_workflow_run_returns_fn_result` — `run` returns the workflow function's
  return value.
- `test_loop_spawner_delegates_to_agent_loop_spawn` — `loop_spawner` adapts an
  `AgentLoop` (spawn called with the prompt).
