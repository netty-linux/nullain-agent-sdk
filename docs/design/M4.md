# Design Document — Milestone M4: AgentLoop v1 (ReAct)

## 1. Objetivo
Implementar o núcleo de raciocínio e execução `AgentLoop` utilizando o padrão ReAct. O loop orquestra a interação entre o histórico da conversa (`Conversation`), o provedor de linguagem (`LLMProvider`), o registro de ferramentas (`ToolRegistry`) e o barramento de eventos (`EventBus`).

## 2. Guardas de Terminação
Terminação garantida por 3 guardas independentes contra loops infinitos:
1. `max_steps`: Limite máximo de iterações do loop (default 25).
2. `max_tokens`: Limite total de consumo de tokens por execução.
3. `timeout`: Limite de tempo de execução real (wall-clock time em segundos).

## 3. Fluxo do Loop ReAct
```
receber prompt do usuário
  → emitir UserMessageEvent
  → enquanto step < max_steps e tokens < budget e tempo < timeout:
       - derivar ConversationState (Conversation.fold)
       - requisitar ao LLMProvider (streaming ou gerado)
       - emitir ModelResponseEvent
       - se não houver tool_calls:
           - quebrar o loop (conclusão com resposta em texto)
       - para cada tool_call em tool_calls:
           - emitir ToolCallEvent
           - tentar executar no ToolRegistry
           - se erro: emitir ToolResultEvent(is_error=True) e registrar reflexão
           - se sucesso: emitir ToolResultEvent(is_error=False)
```

## 4. Reflexão sobre Erro de Tool
Quando a execução de uma tool falha, a resposta de erro é enviada de volta ao contexto do modelo como `ToolResultEvent(is_error=True)` com o diagnóstico do erro para que o modelo reflita e tente uma estratégia alternativa na iteração seguinte.

## 5. Critério de Aceite
- Teste e2e em `tests/unit/test_agent_loop.py` com provider fake validando a criação de um arquivo em ≤ N passos.
- Teste de prevenção de loop infinito demonstrando que as guardas interrompem a execução com `BudgetExceededError` ou encerramento gracioso com `ErrorEvent`.
- `make check` 100% verde.
