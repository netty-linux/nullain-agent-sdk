# P3 — Post-v1 hardening: MCP client + test plan

## P3.19 — MCP client

### Goal
Connect the agent to external **Model Context Protocol** servers over stdio
and expose their tools as `RegisteredTool` entries alongside the built-ins,
so the agent can invoke them through the normal Act loop.

### Design

**Hexagonal port.** A new `nullain/mcp/` package mirrors the `LLMProvider`
pattern:

- `protocol.py` — JSON-RPC 2.0 + MCP wire models (`JSONRPCRequest`,
  `JSONRPCResponse`, `MCPToolDefinition`, `MCPToolResult`, `InitializeResult`).
  All server output is validated through Pydantic (untrusted boundary, like
  LLM output). MCP camelCase field names are kept on the wire via
  `Field(alias=...)` + `populate_by_name=True`, exposed as snake_case in code.
- `transport.py` — `MCPTransport` `Protocol` (port) + `StdioTransport`
  (adapter). Subprocesses are launched **only** via
  `asyncio.create_subprocess_exec` with an explicit argv list — never
  `shell=True` (AGENTS.md rule 6). The reader skips non-matching lines so a
  chatty server cannot desynchronize request/response pairing.
- `client.py` — `MCPClient` does the initialize handshake, `tools/list`, and
  `tools/call`. `register_mcp_tools` bridges each remote tool into a
  `ToolRegistry` as an async-closure-backed `RegisteredTool` named
  `mcp__<server>__<tool>` (collision-safe).

**Permissions.** An MCP server's side-effects cannot be inferred from
arguments, so each wrapper carries a fixed `permission_level`: `ALLOW` when
the server is configured `auto_approve`, else `ASK` (gated through the human
approval loop; fail-closed with no callback). This required adding an optional
`permission_level` to `RegisteredTool`, honored by `ToolRegistry.execute`
*before* the argument-based heuristics. MCP tools are `read_only=False` →
sequential dispatch.

**Config.** `[mcp.servers.<name>]` in `nullain.toml`: `command`, `args`,
`env`, `auto_approve`, `enabled` (`MCPServerConfig` / `MCPConfig`). New
`MCPError` / `MCPProtocolError` / `MCPTransportError` in the error hierarchy.

**Daemon.** `run_agentd` starts MCP clients once at startup (shared
subprocesses), re-registers their tools into each per-session registry, and
closes them in `finally`. A server that fails to initialize is logged and
skipped (structured log, never silently swallowed).

**Injection.** `run_agentd` gained keyword-only injection points
(`provider`, `input_reader`, `output`, `settings`, `mcp_clients`,
`episodic_memory`, `event_store`) so the daemon can be driven in-process for
E2E tests without a real Ollama client, MCP subprocess, or home-dir SQLite.

## P3.22 — Test plan (E2E daemon, native Ollama, TOML, IntentParser)

| Area | File | Coverage |
|---|---|---|
| E2E daemon | `tests/integration/test_e2e_agentd.py` | session lifecycle; permission request/response round-trip over the shared stdin channel (grant + deny); MCP tool registration + invocation through the daemon; invalid-NDJSON error envelope |
| MCP client | `tests/unit/test_mcp_client.py` | handshake, list/call, error + non-JSON handling, registry integration (namespacing, permission levels, fail-closed), `StdioTransport` argv (no shell), and a **real-subprocess** round-trip against a minimal Python MCP server |
| Native Ollama | `tests/unit/test_llm_provider.py` | `/api/chat` generate (text + tool_calls + token counts), native NDJSON streaming, `/api/tags` health check — all via respx, fully offline |
| TOML settings | `tests/unit/test_settings_toml.py` | `load_settings` from `nullain.toml` (router tiers, ollama, MCP servers), defaults when no path, `MCPServerConfig` defaults, `NULLAIN_` env override |
| IntentParser | `tests/unit/test_model_router.py` | empty/whitespace → MEDIUM default, case-insensitive keyword matching, each branch's `intent_type`, determinism |

All new tests are offline (fakes / respx / local subprocess). No network.
