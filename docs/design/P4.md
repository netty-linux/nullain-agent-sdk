# P4 — Diferenciação (pós-paridade)

Itens 23–27 do plano de correção (`COMPARATIVO_E_PLANO_CORRECAO.md`), escopados
como "mês 2+, após paridade". P0–P3 (paridade competitiva) está 100% completo e
validado. O P4 é a camada que diferencia o Nullain dos concorrentes em vez de
empatar com eles.

Cada item é um milestone próprio: mini-design em `docs/design/P4.XX.md`,
aprovação, implementação, `make check` verde, commit. Um por vez.

## Ordem proposta (impacto × viabilidade)

1. **P4.23 — Sandbox fail-closed por padrão.** Diferencial de segurança
   flagship ("Grok é fail-open; você pode ser o seguro por padrão"). Restringe
   subprocess (fs + rede) ao workspace; recusa executar se um sandbox é exigido
   e indisponível. **Plateforma-condicional** (landlock é Linux 5.13+); ver
   `P4.23.md` para a decisão de escopo.
2. **P4.24 — Authority-intersection law p/ subagentes.** Formaliza
   `child_authority = intersection(parent_delegation, child_def, context,
   policy)`. Nenhum concorrente prova isso; constrói sobre o `spawn()` existente.
3. **P4.26 — Tool search (schemas deferidos) p/ escalar MCP.** O cliente MCP
   hoje carrega todos os schemas no prompt; com dezenas de servidores isso
   incha o contexto. Schemas deferidos + busca on-demand.
4. **P4.27 — Workflow orchestrator.** Script determinístico sobre subagentes
   (equivalente ao `Workflow` do Claude). Orquestra fan-out/verificação.
5. **P4.25 — Plugin signing + SBOM + capability manifests.** Maior
   subsistema novo; faz por último porque P4.24/26/27 estabelecem o modelo de
   autoridade e ferramentas que o sistema de plugins vai assinar/manifestar.

## Critério de aceite geral do P4

- `make check` verde (ruff + pyright + pytest) em 3.12 e 3.13.
- Cada item com teste offline (fakes / platform-gated p/ OS-specific).
- Sem `Any` na API pública; `Sandbox`/`Authority`/etc. atrás de `Protocol`.
- Sem dependência nova sem justificativa no PR.
