# P4.24 — Subagent Authority-Intersection Law

> **Law.** A child subagent's effective authority is the meet (greatest lower
> bound / intersection) of four factors:
>
> ```
> effective = parent_authority ∧ delegation ∧ child_def ∧ policy
> ```
>
> A capability is granted to the child **only if all four grant it**. Any single
> denial removes the capability outright — there is no ASK escape from the
> bound. No competitor harness (Claude Code / Grok Build / Gemini CLI) proves
> this invariant; it is the trust property of the multi-agent tree.

## Why it matters

`AgentLoop.spawn` previously let a child inherit the parent's full tool registry
unchanged — a subagent could exercise every tool the parent could, with no
delegation contract. Competitors scope tools (`disallowedTools` wins over
`tools` in Claude; Grok caps spawn depth at 1) but none formalize *authority as
an intersection* across delegation layers. P4.24 makes the bound a first-class,
enforced, test-proven object rather than a convention.

## Model

### `Capability` (`nullain/authority.py`)

A coarse authority dimension a tool may require and a subagent may hold:

| Capability | Tools |
|---|---|
| `READ` | read_file, grep, glob, list_directory, git_status, git_diff, read_memory |
| `WRITE` | write_file, edit_file, git_commit, save_memory, MCP tools (conservative) |
| `EXEC` | bash |
| `NETWORK` | web_fetch |
| `SPAWN` | the right to call `AgentLoop.spawn` |

### `Authority` (frozen dataclass)

```
capabilities: frozenset[Capability]   # intersected at meet
allowed_tools: frozenset[str] | None  # None = universe (identity of meet)
deny_patterns: frozenset[str]         # UNIONED at meet (tighter, never looser)
can_spawn: bool                       # AND-ed at meet
```

`Authority.meet(other)` is the greatest lower bound:
- `capabilities ∩ capabilities`
- `allowed_tools ∩ allowed_tools` (`None` = universe = identity)
- `deny_patterns ∪ deny_patterns`
- `can_spawn = a ∧ b`

The root agent holds `None` (unrestricted — the trust root). Only spawned
subagents carry a materialised `Authority`.

### The four factors

| Factor | Source | How it enters the meet |
|---|---|---|
| **parent_authority** | `AgentLoop.authority` (`None` → `Authority.unrestricted()`) | Clamps delegation: `delegation.meet(parent_authority)` — a parent cannot delegate what it does not hold. |
| **delegation** | `authority=` arg to `spawn` | What the parent explicitly passes; clamped to the parent first. |
| **child_def** | `registry.capability_surface()` | `allowed_tools` = registered tool names; `capabilities` = union of each tool's `requires`. The child is *defined* to use exactly its registry's surface. |
| **policy** | `Authority.from_policy(permission_policy)` | READ always; WRITE/EXEC dropped when the policy default-denies them; `deny_patterns` carried in. Folds the existing, tested permission engine into the lattice. |

```
effective = delegation.meet(child_def).meet(policy_auth)   # delegation already clamped to parent
```

## Enforcement

A single chokepoint: `ToolRegistry.execute` checks `self.authority.permits(name, tool.requires)`
**before** the permission policy, and an authority denial raises
`ToolPermissionError` immediately (never ASK). `AgentLoop.spawn` materialises
the effective authority onto a **scoped child registry** (`registry.scoped(...)`)
that shares the parent's tools + callback but carries the intersected authority
and a projected policy (`_project_authority_policy`: deny union + WRITE/EXEC
default-deny when absent from the effective caps — belt and suspenders, no
capability logic duplicated).

`SPAWN` is enforced in `spawn` itself: a loop whose authority has
`can_spawn=False` raises `NullainError` — depth is capped at the gate, not by
convention.

## Backward compatibility

- `spawn(authority=None)` (the default) → child inherits an unrestricted view,
  no gate applied. All pre-P4.24 callers and tests are unchanged.
- `ToolRegistry(authority=None)` (the default) → no gate. The root agent and
  existing direct callers behave identically.
- `RegisteredTool.requires` defaults to `frozenset()` (capability-neutral);
  built-in tools declare `requires` explicitly. `ask_user` is
  capability-neutral (governed solely by the allowed-tool set).

## Honesty / scope

- **v1 capability set is coarse** (READ/WRITE/EXEC/NETWORK/SPAWN). Finer
  resource authority (per-path write bounds, per-host network) is deferred —
  the workspace path bound already lives in `PermissionPolicy` +
  `resolve_and_validate_path`, and network is governed by the P4.23 sandbox.
  This layer composes with those, it does not replace them.
- **MCP tools** conservatively `requires={WRITE}` (side-effects not
  introspectable): a read-delegated subagent cannot call them. A read-only MCP
  server could declare otherwise once MCP capability hints are surfaced
  (follow-up).
- The law governs **subagent delegation**; the root is the trust root
  (`authority=None` = unrestricted). Restricting the root via a materialised
  authority is supported (the constructor accepts `authority=`) but not wired
  from `nullain.toml` yet — a follow-up config knob.

## Proof (tests/unit/test_authority.py)

- `test_meet_*` — meet intersects capabilities/allowed-tools, unions denies,
  ANDs can_spawn; universe is identity.
- `test_from_policy_projects_levels_and_denies` — the policy factor.
- `test_capability_surface_unions_tool_requires` — the child_def factor.
- `test_registry_gate_*` — the chokepoint denies missing capability / disallowed
  tool, allows permitted calls; root registry has no gate.
- `test_spawn_read_only_delegation_blocks_write` — **the law, end-to-end**:
  parent delegates READ-only; child has `write_file` in its registry and
  requests it; the file is **never created** even though child_def + policy
  both permit writes (delegation removed WRITE).
- `test_spawn_clamps_delegation_to_parent_authority` — a parent lacking WRITE
  cannot delegate WRITE; the child's write is still blocked.
- `test_spawn_refuses_without_spawn_capability` — depth cap at the gate.
- `test_spawn_policy_factor_drops_write_when_policy_denies` — the fourth factor
  is enforced, not just the first three.
- `test_spawn_without_authority_is_backward_compatible` — `authority=None`
  preserves pre-P4.24 behavior (write succeeds under an ALLOW-all policy).
