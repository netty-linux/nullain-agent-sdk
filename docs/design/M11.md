# M11 — Diferenciação (Fase 4)

> Uma fase por sessão (M8→M9→M10→M11). Este doc é o mini-design para revisão
> antes de implementar. Fonte: `PROMPT_FASES_CORRECAO.md` Fase 4.

## 4.1 — Checkpoints e undo

- Novo `CheckpointStore` em `nullain-tools/src/nullain_tools/checkpoints.py`,
  injetado em `create_filesystem_tools` (mesmo padrão do `FileAccessTracker`),
  criado por sessão no daemon.
- `snapshot(path)`: antes de cada escrita (`write_file`, `edit_file`,
  `multi_edit`), guarda o conteúdo atual do arquivo.
- **Mecanismo de armazenamento** (decidido e justificado): quando o workspace é
  um repositório git, usar `git hash-object -w` (blob no object database) +
  `git cat-file blob` para restaurar — **nunca** toca índice, refs ou histórico
  do usuário (requisito duro). Fallback para cópia em `.nullain/checkpoints/`
  quando não é repo. Manifesto mapeia `relpath -> blob_hash` (ou caminho da
  cópia). Subprocess por lista de args (regra 6).
- Tool `undo`: restaura o checkpoint mais recente (pilha por sessão) e o remove.
- Retenção limitada: últimos `max_checkpoints` (default 20) ou `max_bytes`
  (default 50 MB), com eviction dos mais antigos.
- `requires={Capability.WRITE}` para `undo`.

## 4.2 — Cliente LSP

- Novo módulo `nullain-sdk/src/nullain/lsp/` com `config.py`
  (`LSPServerConfig`/`LSPConfig`, seção `[lsp.servers.<lang>]` no `nullain.toml`,
  mesmo formato do `[mcp.servers.*]`) e `client.py` (`LSPClient` sobre stdio
  JSON-RPC — framing inspirado em `mcp/transport.py` mas **independente**, sem
  acoplar os dois).
- Handshake: `initialize` → `initialized`; depois requests
  `textDocument/diagnostic` (pull, LSP 3.17), `textDocument/definition`,
  `textDocument/references`, `textDocument/hover`.
- Tools `lsp_diagnostics(path)`, `lsp_goto_definition(path, line, col)`,
  `lsp_find_references(path, line, col)`, `lsp_hover(path, line, col)` —
  inferem a linguagem pela extensão do arquivo e roteiam para o servidor
  configurado.
- **Fail-soft** (mesmo padrão de `_load_mcp_clients`): servidor indisponível ou
  falha é logado e retorna `ToolResult` informativo, nunca derruba a sessão.

## 4.3 — `IntentParser` com classifier real

- Adicionar `classifier_model: str | None = None` ao `RouterConfig` (campo
  morto desde o comparativo) e ao `nullain.toml.example`.
- `IntentParser` ganha `async parse_async(prompt, provider, model)`: heurísticas
  determinísticas primeiro; quando nenhuma bate com confiança, chama o
  `classifier_model` (tier `fast`) com timeout curto para classificar
  intent + complexidade. Fallback para a heurística em qualquer falha.
- Cache por hash do prompt dentro da sessão. `parse` (síncrono, só heurística)
  permanece para compatibilidade; o loop passa a chamar `parse_async`.

## 4.4 — Subagente em worktree isolado

- `spawn` ganha `isolation: Literal["worktree", None] = None` (default in-place,
  backward-compatible).
- `isolation="worktree"`: cria `git worktree add --detach <tmpdir>` (detached,
  sem poluir branches), o filho roda com `workspace_root = tmpdir` (registry
  escopado), e ao terminar o resultado é integrado (copia arquivos alterados de
  volta ao workspace do pai) ou descartado se nada mudou.
- Limpeza garantida do worktree (`git worktree remove --force`) em `finally`,
  inclusive em falha/cancelamento (usa o cancelamento do M10).
- A lei de intersecção de autoridade (P4.24) é **preservada integralmente** — o
  isolamento é adicional ao gate de capability, nunca substituto.
