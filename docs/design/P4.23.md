# P4.23 — Sandbox fail-closed cross-platform

## Goal
Confinar a execução de subprocess (tool `bash` e, no futuro, qualquer tool que
spawn) em um sandbox OS-level que isola **filesystem + rede**, com semântica
**fail-closed**: se um sandbox é exigido e indisponível, RECUSA executar em vez
de rodar sem isolamento. Diferencial de segurança flagship — "Grok é fail-open;
você é o seguro por padrão" (Anexo B do plano).

## Arquitetura (hexagonal)

Novo `nullain/tools/sandbox/` (subpacote, separado do `sandbox.py` atual que vira
`sandbox/runner.py`):

```
sandbox/
  port.py        # Sandbox (Protocol), SandboxOptions, SandboxUnavailableError
  selector.py    # select_sandbox(settings) -> Sandbox  (escolhe o adapter da plataforma)
  runner.py      # run_command(...) — mergeia kwargs do sandbox + create_subprocess_exec
  adapters/
    none.py      # NoSandbox — só quando config enabled=false
    landlock.py   # Linux >=5.13
    seatbelt.py   # macOS
    windows_job.py # Windows
```

### Port
```python
class Sandbox(Protocol):
    @property
    def name(self) -> str: ...  # "landlock"|"seatbelt"|"windows_job"|"none"
    def available(self) -> bool: ...  # este adapter isola DE VERDADE neste OS/kernel?
    def prepare(self, argv, *, cwd, env, allow_paths) -> dict[str, Any]:
        ...
        # kwargs a mergear em create_subprocess_exec (preexec_fn / creationflags / etc.)
```

`run_command` chama `sandbox.prepare(...)`, mescla os kwargs, lança. Se
`sandbox.required and not sandbox.available()` -> raise `SandboxUnavailableError`
ANTES de qualquer subprocess (fail-closed).

## Adapters — o que cada um isola DE VERDADE

| Plataforma | Adapter | FS隔离 | Rede隔离 | Notas |
|---|---|---|---|---|
| Linux ≥5.13 | `LandlockSandbox` | ✅ landlock (rw workspace + ro /usr/bin + rw tmp) | ✅ `unshare(CLONE_NEWNET)` | puro ctypes, sem dep nova |
| Linux <5.13 | — | ❌ | ❌ | `available()=False` -> fail-closed se required |
| macOS | `SeatbeltSandbox` | ✅ profile `sandbox-exec` | ✅ `deny network*` | `/usr/bin/sandbox-exec` com argv (não shell) |
| Windows | `WindowsJobSandbox` | ⚠️ parcial | ⚠️ parcial | Job Object (contenção de processo, impede escape/spawn-fora) + `CreateRestrictedToken` (baixa integridade). **FS isolation real no Windows exige AppContainer** — fora de escopo v1; o `PermissionPolicy` existente (resolve + is_relative_to) continua sendo o controle de fs em Windows v1. AppContainer = follow-up explícito. |
| qualquer | `NoSandbox` | ❌ | ❌ | só quando config `sandbox.enabled=false` |

**Honestidade Windows:** Job Object sozinho NÃO restringe caminhos de arquivo.
O valor real no Windows v1 é (a) contenção de processo (filho não escapa/spawna
fora do job), (b) token de baixa integridade, (c) **fail-closed** (recusa se
exigido e indisponível), e (d) o `PermissionPolicy` já valida paths. Isolamento
de fs via AppContainer é um follow-up sinalizado, não hidden.

## Config (`nullain.toml`)
```toml
[sandbox]
enabled = true      # default true
required = true     # default true — fail-closed se adapter indisponível
allow_paths = []    # paths extras além do workspace (ex: cache do pytest)
deny_network = true # default true
```
`NullainSettings.sandbox: SandboxConfig`.

## Testes (offline / platform-gated)

- `FakeSandbox` (records `prepare`, `available` configurável).
- **fail-closed** (cross-plat): `required=true` + `available()=False` -> `run_command` levanta `SandboxUnavailableError`, nenhum subprocess.
- **selector**: `select_sandbox` escolhe o adapter correto por plataforma; `enabled=false` -> `NoSandbox`.
- **Linux** (gated `sys.platform.startswith("linux")` + kernel ≥5.13): `LandlockSandbox.available()=True`; teste real de escape: bash sandboxed NÃO consegue escrever fora do workspace (cria arquivo em path externo -> negado).
- **macOS** (gated): `SeatbeltSandbox` gera profile com deny network; teste de escape de fs gated (ou só geração do profile string, sem exec).
- **Windows** (gated): `WindowsJobSandbox` cria Job Object; filho no job; `available()` reflete kernel32.
- Sem rede no CI: todos os testes de adapter OS-specific usam subprocess LOCAL (não rede). Escape tests usam `tmp_path`.

## Escopo explícito fora de v1
- AppContainer (Windows fs isolation real).
- seccomp fino (filtrar syscalls além de rede/netns).
- Sandbox p/ tools não-bash (MCP subprocess, hooks) — design permite, mas wire só no bash nesta fase.

## Critério de aceite
- `make check` verde 3.12/3.13.
- fail-closed provado por teste cross-plat.
- Linux escape test verde no CI (Ubuntu).
- `Sandbox` atrás de `Protocol`; sem `Any` na API; sem dep nova (ctypes puro).
